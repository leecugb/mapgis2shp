# 线型库解析逻辑总梳理（2026-10-19 裁定版）

> 依据：用户逐行目视裁定（2026-10-13/14 基线 + 2026-10-19 扩展）。
> 实现：`pymapgis.linesty`（feature_rhythm / dotline_params / linedot_params
> / compose_feature_style）+ `pymapgis.linesty_adjudicated`（裁定表，
> 仓内专用不进发布件）。测试全绿（tests/test_pure.py，含
> TestLinestyTruncatedFlag 截断标志锚）。

## 一、总架构

```
(LINESTY.lib, linetype, aux) ──→ LinestyLib.decode(linetype) ──→ LineStyle
                                        │
                     feature_rhythm(style, aux) ──→ {kind, lines, dots,
                                        │            verticals?, teeth?,
                                        │            period_mm}
                     dotline_params / linedot_params（16|0/17|0 点线族）
```

- **记录号 = 线型号（1-based）**；记录 = 子线指针表 + N 条子线
- **子线 = [u16 n][n×6B 元素模板 (unit, marker, offset)][f32 载荷区]**
- **aux 选择主记录子线索引**：`(lt, aux)` 渲染 `sub[aux]`；aux 记录的笔
  不渲染（3|1 红实线笔弃画裁定）——"记录内子线渲染选择规则"的定案实例
- **未裁定线型诚实返回 None**，绝不臆断

## 二、元素模板语义

| unit | 含义 | 消费 |
|---|---|---|
| 0 | 空移/线对 | marker×2 个 f32 |
| 1 | **坐标列填充多边形**（211/38/208 锚）| marker×2 个 f32（点对）|
| 2 | 随动/档 | marker×2 个 f32 |
| 3 | 画点 | marker×2 个 f32（点对）|
| ≥5 | 子图号引用（258/259 圆点、1280 等）| 同上 |

注意：marker 的消费律有变体（58/127/153 的三元组档、括号三点组——
每线型以实测消费为准，逐元素对账是纪律）。

## 三、f32 载荷的通用语义模式

1. **坐标对序列**：`(x0,y0), (x1,y1), …`——每对是点或线端点；
   **y 是真实坐标不是噪声**（51|0 教训）
2. **点三元组**：`(x, y, r)`——unit=3 元素（50/51/16|2/58 锚）
3. **档结构**：`(x, y0, y1)` ×N 遍冗余——x=档值（标签非位置）、
   |y0|=刻度高、y1=顶端（3|5/4|3 锚）；**档文件序 = 间隙序**
4. **尾段线**：末尾 6 对 = 三线（连续对成线，y 为噪声忽略）；
   127|0 教训：**尾段元素同样是图形，必须消费**
5. **重复坐标 = 冗余**（153 锚：不叠画不加粗）

## 四、周期规则（两犯教训定案）

- **基本单元等间距族**：周期 = 相邻线起点差的最小正值（38|1：0.5）
- **单线族**：周期 = 最大线终点（48|1：1.0）
- **记录末 x ≠ 周期**（38|1/48|1 教训）

## 六、新线型落码三查纪律（docstring 已制度化）

1. elements 结构先行（unit/marker 消费与角色）
2. (x,y) 对角色判定（线端点/点/参数）——不得套已裁定模板
3. 周期来源（单元间距/最大线终点）
4. 渲染对账：全部元素必须消费（127 教训）
5. 分支守卫：前序分支正向 `style.no == X`（5|0、51 教训）
6. 每行 ≥1 条逐值锚定测试 + 全量回归
