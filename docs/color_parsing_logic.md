# 颜色解析逻辑、真值链与当前实现

## 1. 当前结论

颜色按角色和库结构解析，不再把 Colorlib 当作所有图元的唯一色表：

| 颜色角色 | 当前解析规则 |
|---|---|
| WP 面填充色 `fill_color` | 默认 `fill_library="auto"`：存在 Pcolor 时按 32B 节点解码；无 Pcolor 时才使用 Colorlib |
| WP 花纹色 `pattern_color` | Colorlib 直接解码 |
| WL 主线色 `color`、独立辅助色 `aux_color` | Colorlib 直接解码 |
| WT 点/子图色 `color` | Colorlib 直接解码 |
| Subgraph 内部填充色 | 按 Subgraph `Element` 的填充模式与色号处理，不套用 WP 填充库 |

Pcolor 与 Colorlib 的部分常规色号并不一致，因此 Pcolor 不能无条件替换其他颜色角色。`fill_library="color"` 仅保留为旧路径对照；显式 `fill_library="pcolor"` 要求文件存在。

**最终原生渲染不启用人工覆盖。** `color_overrides` 和 `unit_color_overrides` 只用于明确标记的专题图或对照实验。对话框真值用于发现和验证库结构，不直接作为原生输出色表。

## 2. WP 字段布局已经验证

当前 Reader 布局为：

- `u8 @1`：class；
- `u8 @5/@6/@7`：24 位面环索引偏移，**不是颜色**；
- `u16 @9`：填充色；
- `u16 @13`：图案号；
- `u16 @17/@21`：图案高/宽的 float32 高 16 位；
- `u8 @23`：图案色；
- `u8 @30`：图层。

这些字段已与 MapGIS 区参数对话框对账。`Qp3pal` 的填充色确为 602，`Qhfl` 确为 652，字段错位不是本次颜色异常的根因。

## 3. Colorlib：连续 4B 记录，KCMY 通道

`ColorLib` 使用 16B 头部后的连续 4B 记录：

```text
offset(N) = 16 + 4N
factor = (255 - K) / 255
R = round((255 - C) * factor)
G = round((255 - M) * factor)
B = round((255 - Y) * factor)
```

常规锚：1=黑、9=白、173=`(255,163,163)`、175=`(255,0,0)`。602/652 在 **Colorlib** 中分别为 `(206,217,206)`、`(51,204,76)`；但这些不是 WP 填充应使用的 Pcolor 节点值。

`channel_order="YMCK"` 只作为其他安装环境的显式备选，不自动切换。

## 4. Pcolor：32B 节点，而非 16B + 4B 槽表

2026-11-07 通过原生对话框真值定位到真实布局：

```text
colour N → 32-byte node (N + 3)
K/C/M/Y  → node offset +28
```

当前库共有 **4098 个颜色节点（0–4097）**，末尾另有 28 字节非颜色节点数据。节点前 28 字节属于辅助信息，RGB 解码不需要解释它们。

旧模型 `offset = 16 + 4N` 会把节点中的指针、标志和辅助字节误当颜色，因此产生“602/652 全零”“扩展色不存在”等错误结论。

### 4.3 原 25 个未知色号全部解决

真实 12 层原有 **25 个未知色号、418 次灰色回退**，现在均为 **0**。其中此前挂账的 1167/1168 分别为：

- 1167：`(255,255,127)`；

- 1043/1044 为 `(255,255,229)`，不是推断的 `(255,255,215)`；

- 1425/1426/1427 分别为 `(230,197,148)`、`(229,188,128)`、`(227,177,107)`。

所以旧 `family_inferred_temporary` 不再参与原生输出。

## 5. 公共实现

- `PcolorLib(path, channel_order="KCMY")`：按 32B 节点和 +28 通道偏移读取；全零 KCMY 可表示白色。
- `GraphicLibraries.from_directory()`：四个必需库之外，可选加载 Pcolor。
- `GraphicRenderer(fill_library="auto")`：WP 填充优先 Pcolor，无 Pcolor 时使用 Colorlib；其他角色始终使用 Colorlib。
- `fill_library="pcolor"`：强制 Pcolor，文件缺失时明确报错。
- `fill_library="color"`：仅用于复现旧的 Colorlib-only 对照结果。
- 人工覆盖仍需显式提供，默认关闭；未知颜色、未知填充和回退次数继续写入报告。

实现：[pcolor.py](../src/pymapgis/pcolor.py)、[graphic.py](../src/pymapgis/graphic.py)。

## 7. 后续新增颜色证据的规则

1. 先确认字段与颜色角色，不把 ring pointer、pattern number 或 class 当成颜色。
2. 新真值首先用于验证节点号、通道偏移和库版本，不直接建立单元色覆盖。
3. 其他图幅或安装环境单独记录库哈希与真值，不把 JWD 节点模型无条件外推为所有版本。
4. 新增证据后重新执行真实 12 层回归，检查未知色报告，而不是只看全图是否“更鲜艳”。
