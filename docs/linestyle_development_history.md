# LINESTY 线型参数解析逻辑开发史

## 1. 范围与分层

本项目的“线型参数解析”实际包含四层，不能混为一谈：

1. **`.WL` 图元参数**：线型号、辅助线型号、线宽、X/Y 系数、颜色、辅助色、图层和透明输出。
2. **`LINESTY.lib` 记录结构**：记录索引、子线、元素模板和 f32 载荷。
3. **几何节奏与渲染**：周期、子线变体、辅助记录叠加、沿原线戳印和显示单位换算。
4. **地质语义**：断层、整合/不整合、岩性渐变等，属于辅助裁定，不属于 `mapgis2shp` 的格式解析核心。

当前原则是：**库参数为主，已验证裁定为辅；已验证变体优先走 `feature_rhythm()`，其他记录由结构参数解析，未解决变体不得用通用几何替代。**

## 3. `.WL` 图元参数的定稿布局

以下字段由 Reader 直接暴露，渲染器不应再从其他字节猜测：

| 字段 | 字节 | 类型 | 当前含义 |
|---|---:|---|---|
| `linetype` | 22–23 | int16 | 主线型号（1-based） |
| `aux_linetype` | 24 | uint8 | 辅助线型号/辅助记录号 |
| `aux_flag` | 25 | uint8 | 辅助标志字节；与 aux 分开读取 |
| `color` | 26–27 | int16 | 主线颜色索引 |
| `width` | 30–33 | float32 | 图元线宽（mm） |
| `x_coef` | 35–38 | float32 | 沿线方向系数 |
| `y_coef` | 39–42 | float32 | 垂线方向系数 |
| `aux_color` | 43–44 | int16 | 辅助色；0 表示随主色 |
| `layer` | 47 | uint8 | 图层 |
| `transparent` | 48 | uint8 | 透明输出标志 |

特别教训：`@24` 和 `@25` 不能合并成 int16。否则 `@25=1` 会被错误地拼成 `aux=256`，产生并不存在的辅助线型。

## 4. LINESTY.lib 结构解析的成熟过程

### 4.1 记录与索引

当前 `LinestyLib` 读取：

```text
[u32 count=860][u16 reserved]
N × [u32 record_offset + u16 subline_count]
记录区：N × [u32 subline_offset + u16 subline_length]
```

- `record_offset=0` 是空槽；当前库中仅 860 号为空。
- `record_bounds()` 通过预计算映射实现 O(1) 查询，避免全库扫描退化为 O(N²)。
- 子线指针非法时设置 `truncated=True`，不再把“真空”和“损坏”混为一谈。

### 4.2 元素模板

每个子线由以下结构组成：

```text
[u16 n][n × 6B (unit, marker, offset)][f32 payload]
```

通用消费规则在 2026-10-20 定稿：

- `offset` 是该元素在 f32 载荷区的起始索引；
- 消费区间为 `[offset_i, offset_{i+1})`，最后一个元素到载荷末尾；
- 默认 `2×marker` 只适用于部分记录，不能替代 offset；
- 不可解析时保持 `None`，不得伪造分组。

### 4.3 从形状启发式到结构参数

旧 `payload_geometry()` 主要按载荷形状推导线段、折线、填充和点，并含历史填充裁定。当前新增 `parameter_geometry()`：

- 不读取 `style.no`，不查裁定表；
- 显式 `UNIT_FILLED_POLY` 才输出填充；
- 显式 `UNIT_DOT` 才确定画点；
- 其他三点载荷的 `filled` 为 `None`，报告为 `unknown_fill`；
- `unit=0` 不能直接当空移，两个坐标对仍然是可见线段。

这使解析结果由 **unit + offset + marker + 实际载荷**共同决定，而不是由线型号决定。

## 5. 节奏、子线和辅助记录的当前规则

### 5.1 已验证变体优先，结构参数兜底

`GraphicRenderer._rhythm()` 对已验证变体优先使用 `feature_rhythm()`；其他记录才尝试 `LineStyle.rhythm()` 或 `parameter_geometry()`。已验证但未解决的变体直接返回 `None`，不再回退到另一种形状。

### 5.2 子线变体而非盲目叠加

2026-11 的真实 48 号样例证明，“全部子线展开”会把 `48|0` 与 `48|1` 混画，并造成基线周期错误。当前规则：

- 非实线子线按变体选择，默认选择子线 0；
- 全部 24B 实线笔才作为真实叠加层保留；
- 周期同时考虑元素 offset 与载荷实际 x 范围，避免把连续基线截成短段。

48|0 的正确结果是：**连续基线 + 上方平行断线**，而不是两组变体叠加。

2026-11-07 对照 `_xj115_boundary_002_no_fault.svg` 进一步发现，绘制层曾把抬升断线固定为 Matplotlib `(3,2)` 点模式，绕过库内段长并忽略 `x_coef`。当前已改为：基线按原线链长截取并保留原始折点，非零 y 层生成平行曲线，所有断线区间均来自 `feature_rhythm()` 的 `(x0,x1,y)`，由 `x_coef/y_coef` 分别控制沿线节奏与垂线偏移。

同一参考审计将 16/17 族的重复实心圆引用固化为几何并集：同坐标仅保留最大半径，不再重复叠画；空圈和未知填充状态不适用该规则。

38|2 进一步审计发现，通用戳印曾把零偏移基线简化为周期端点直线，跳过曲线内部折点。当前所有零偏移线段均按原线链长裁切，并保留区间内全部源顶点；37 条真实 38|2 的 782 个源顶点缺失 0、最大偏差 0.0。非零恒定偏移线也统一使用完整平行曲线，并以原线链长控制相位，避免其他图幅出现同类弦线近似。

### 5.3 主记录和辅助记录

完整图元不能把 aux 一律当成主记录子线索引，也不能一律当成独立辅助线。2026-11-07 对照 SVG 与真实组合后，当前公共渲染定稿为：

- `0 < aux < len(main.sublines)`：选择主记录子线变体，不叠加独立辅助记录；
- `aux >= len(main.sublines)`：主记录使用默认变体，辅助记录独立解码并叠加；
- 2 号族是已裁定例外：2|x 的越界等价虚线仍属主记录语义，不叠加 aux；
- 辅助色只在独立辅助记录存在时使用，否则沿用主色。

因此 `16|1` 不多出实线，`38|2` 只画齿线变体，`65|4` 消费第 4 子线（6 个填充单元、30.4 mm 周期），`1|2` 保留独立辅助虚线。本幅 44 条非零 aux 中，实际独立辅助图案为 **5 条 1|2**；37 条 38|2 与 2 条 65|4 均为变体选择。

18|0 对照还发现零纵向长度竖线在起点被裁剪的问题。当前竖刻度按 `[0,total)` 取值，保留原点刻度且不在闭合线终点重复。

### 5.4 显示单位

Matplotlib `transData` 输出像素/地图单位，而线宽和散点面积使用点（1/72 英寸）。当前换算为：

```text
points_per_unit = pixels_per_unit × 72 / figure.dpi
```

避免同一图在提高 DPI 时线宽和点径被同步放大。

## 6. 旧函数和裁定资产的角色

| 资产 | 当前角色 |
|---|---|
| `LinestyLib.decode()` | 正式结构解析入口 |
| `SubLine.consumption` / `payload_groups()` | 正式 offset 消费与切片 |
| `SubLine.parameter_geometry()` | 其他记录的结构参数几何入口 |
| `LineStyle.rhythm()` | 库内直接节奏结构的优先入口之一 |
| `feature_rhythm()` | 已验证变体的优先路径，保留其正确周期、相位和子线选择 |
| `payload_geometry()` | 旧形状推导与填充裁定，兼容使用 |
| `render_ops()` | 历史结构化操作码与部分人工规格，不作为公共原始渲染主路径 |
| `linesty_adjudicated.py` | 仓内辅助裁定，**不进入 wheel/sdist**；缺失时相关语义接口降级 |
| GZBD/GZEEB 语义表 | 地质解释资产，不纳入 mapgis2shp 的格式承诺 |

## 7. 当前验证状态

- LINESTY 全库：**859/859 非空线型可由结构参数生成几何**；唯一未解析槽位 860 为空。
- 真实 12 层：7094 个要素全部进入绘制报告，主线与辅助线实体回退均为 0。
- 子图：581 个成功、0 个未解析。
- 完整包测试（含安装态 CLI、仓内真实 Colorlib/Pcolor、真实 12 层与 SVG 参考线型）：**324 passed，0 skipped**。
- Wheel 已构建并通过内容及导入检查，包含 `graphic.py`、`pcolor.py` 等模块。

## 8. 尚未闭合的问题

1. **结构覆盖不等于原生视觉等价**：尚缺全 859 型的 MapGIS 原生样张逐型对照。
2. `UNIT_FOLLOW`、笔档选择、点在线侧侧别等仍需原生参数或样张确认。
3. 未确定的填充状态只能报告，不能把 `unknown_fill` 当作已裁定空心或实心。
4. 辅助线型的组合仍需在目标 MapGIS 安装环境中做视觉确认，尤其是非零 aux 记录。
5. `render_ops()` 中仍有历史逐型规格，但 `feature_rhythm()` 只用于已验证变体；必须防止通用几何回退覆盖这些已验证结果。
6. 颜色与线型应分别审计；通道模型（KCMY/YMCK）必须显式选择，不能由几何解析结果反推。

## 9. 后续开发建议

1. 保持结构解析只从库参数推导；已验证变体规则集中在 `feature_rhythm()`，新增语义先用于验证，不再把逐线型号分支扩散到通用几何路径。
2. 为每类结构建立回归：单实线、全部实线笔、非实线变体、inline rhythm、填充单元、点三元组、未知填充和非法指针。
3. 将 48|0/48|1、实际 44 条非零 aux（其中 5 条独立辅助）、WP 内孔、WT 排版与 DPI 换算列为强制验收案例。
4. 用 MapGIS 原生样张补齐“结构已解”到“显示已证实”的最后一层证据，并按结构类别而不是线型号发布支持矩阵。
5. 对无法证明的字段或填充状态继续返回 `None` 和报告项，禁止静默猜解。
