## 4. 仍存在的数据正确性缺陷

### R1 — 高：AEA/LCC 的 `lat_1` 被写成25°

位置：`src/pymapgis/writer.py:659-697`、`:745`。

原因：头部“常量”f32 图案实际包含原生 double 的高4字节。当前只对偏移195做 AEA/LCC 特判，却仍用187的图案覆盖 `lat_1`（起始偏移183）的高4字节。

本轮独立复现：

```text
AEA：请求 lat_1=36.25°，Reader 回读 lat_1=25.0°
LCC：请求 lat_1=36.25°，Reader 回读 lat_1=25.0°
```

现有测试使用 `lat_1=25°`，其字节恰好与覆盖图案一致，因此测试未能发现问题。这会错误定义投影并造成大范围位置误差，应优先修复并增加非25°回归。

### R2 — 中：追加属性列时新值静默丢失

位置：`src/pymapgis/writer.py:365`、`:466-467`、`:1887-1892`。

原因：Reader 派生图层完全复用旧 `record_length`；新增列按声明长度而不是实际存储长度计算偏移，最终被打包到旧记录长度之外并截断。

本轮独立复现：

```text
新增字段描述符存在：True
读回值：["", "", ""]
```

影响自然的“读取→追加字段→写出”工作流。新增列时必须重新计算记录长度和物理偏移，不能复用旧记录长度。

### R3 — 中：面透传指纹丢弃小幅真实几何编辑

位置：`src/pymapgis/writer.py:2247` 附近。

原因：面透传指纹使用面积和四位小数包围盒；不改变包围盒的小幅内部顶点编辑可能被视为未修改。

本轮独立复现：

```text
编辑后输入顶点数：6
写出后读回顶点数：5
输入面积：0.999985
输出面积：1.0
```

即输出静默恢复为编辑前面几何。透传必须使用足够严格的几何指纹，或在无法证明未修改时重新编码。

## 5. 功能与覆盖边界

### 5.1 WT 原生文本池

Reader 尚未解码 WT section-1 文本池；Writer 新文件写入2字节空池。只存于原生文本池而没有 `CHFCED/LABL` 属性的注记无法通过公共 API 恢复。原始段透传可保留旧文本池，但修改文本属性不会同步更新池内容。这是明确的功能缺口，不能把“属性文本注记可用”表述为“全部原生文本池已支持”。

### 5.2 清洁环境测试依赖

`README` 的开发安装流程与 `[dev]` 依赖仍不足：测试收集还涉及 PyMuPDF、GDAL/osgeo、lxml 和 geosciml4china，其中后者由示例通过非标准兄弟目录逻辑引用。当前474项通过依赖已安装的 Anaconda 环境和显式外部 `geosciml4china` 路径；不能直接据此宣称全新环境可复现。

### 5.3 真实数据常驻回归不足

原始 JWD、USGS 原生六层和正式 JWD GeoPDF 测试在清洁包中跳过。七层 USGS 加工数据与五库已随包且实际渲染成功，但目前测试套件尚没有把这一组合作为默认、常驻的真实渲染回归。默认 CI 仍较依赖合成/Fake 库。

### 5.4 其他渲染边界

- 地理 CRS 直接渲染使用赤道 `111320` 近似，未在 Renderer 内警告；正式流程应先投影。
- 普通 Matplotlib PDF 接口仍存在，不自动提供严格比例尺或 GeoPDF 保证。
- 单点子路径固定 `ms=2.0`；栅格预览图案使用双线性插值，正式全矢量路径不使用该插值。
- 符号尺寸外部资料支持“库内基准几何×矢量比例参数”；WT 高宽不等时的 `min(width,height)` 仍需原生样张验证。
